# 完善装修阶段决策辅助

## Goal

把流程页从“阶段时间轴”进一步变成当前阶段的执行入口。用户进入流程页时，先看到本阶段完成度、下一项行动、关键避坑、采购和验收入口，再决定是否查看完整时间轴，降低在大量阶段信息中找不到重点的成本。

## What I Already Know

* 项目是零依赖、零构建的 vanilla JS / HTML / CSS 单页应用，用户状态保存在 `Store.state`。
* `stages.js` 已有 14 阶段时间轴、阶段展开、任务勾选、日期设置、避坑、采购和验收入口。
* `App.currentStage()`、`App.stageProgress()`、`App.stageTasks()` 已提供当前阶段与任务进度计算，应继续复用。
* 首页已经提供行动中心，本轮应补足流程页进入后的阶段决策上下文，而不是重复首页待办。
* `guide.js` 支持 `materials` 与 `accept:<id>` 参数跳转，阶段数据包含 `warnings`、`buy`、`acceptIds`、`goal` 等信息。

## Assumptions

* 当前阶段摘要只使用已有静态知识和已有任务状态，不新增持久化字段。
* 完整时间轴仍然保留，摘要只负责定位重点，不改变已有任务、日期和验收操作。
* 用户从首页或其他入口带阶段参数进入时，摘要应与该阶段一致；无参数进入时使用当前进行中的阶段。

## Open Questions

* 无。

## Requirements

* 流程页顶部展示当前阶段摘要：阶段名称、阶段目标、完成数量/总数和进度条。
* 摘要展示本阶段第一项未完成任务作为“下一步行动”；点击只负责展开并定位当前阶段，不在摘要提供重复完成控件。
* 摘要展示最多 2 条本阶段高优先级避坑提醒，避免用户必须先展开阶段卡片才能看到风险。
* 摘要展示本阶段第一条采购事项；点击进入现有建材购买日历，不重复展开完整采购列表。
* 摘要展示本阶段第一个验收清单入口；没有验收清单时不展示空入口。
* 阶段已完成时，摘要展示完成状态，并保留查看阶段详情的入口。
* 全部流程完成时，摘要展示入住收尾提示，并仍可查看最后阶段。
* 摘要导航沿用现有事件代理、`App.rerender()` 与阶段聚焦逻辑；任务完成仍在完整阶段清单中操作。
* 移动端摘要内容不横向溢出，操作入口可换行且保持可点击区域。
* 摘要固定展示；首次进入流程页时默认展开当前阶段，其他阶段折叠；从摘要进入下一步时聚焦当前阶段。

## Acceptance Criteria

* [ ] 进入流程页首屏能明确识别当前阶段和下一项未完成任务。
* [ ] 当前阶段有未完成任务时，摘要显示第一项未完成任务；勾选后进度与流程页其他区域一致。
* [ ] 当前阶段存在避坑、采购、验收数据时，摘要分别显示对应入口；缺少数据时不显示空模块。
* [ ] 点击摘要的下一步行动会展开并聚焦对应阶段，不产生重复路由或错误滚动。
* [ ] 首次进入流程页时只有当前阶段展开，其他阶段不会同时展开造成信息堆叠。
* [ ] 从首页带阶段参数进入流程页时，摘要和展开阶段使用该参数，而不是重新回到全局当前阶段。
* [ ] 当前阶段已完成或全部完成时，摘要仍有清晰状态和详情入口。
* [ ] 旧的时间轴、任务日期、自定义任务、验收跳转和阶段一键完成功能不回归。
* [ ] 窄屏下无横向溢出，动态任务和阶段名称均正确转义。
* [ ] 全部 JavaScript 通过语法检查，`git diff --check` 通过。

## Definition of Done

* 完成流程页当前阶段摘要及必要样式。
* 保持现有 localStorage 数据结构和路由兼容。
* 更新 README 功能概览或前端交互规范（如形成长期契约）。
* 完成源码级静态验证；浏览器手测能力允许时验证核心点击路径。

## Out of Scope

* 新增独立的施工日志、照片上传、云同步或多人协作。
* 修改装修知识库的阶段内容和价格数据。
* 重写现有 14 阶段时间轴或新增日期自动排程。

## Technical Approach

* 在 `js/views/stages.js` 增加当前阶段摘要 helper，使用 `App.currentStage()`、`App.stageProgress()` 和 `App.stageTasks()` 生成 HTML。
* 复用现有 `data-action="toggle-stage"`、`data-action="nav"` 和 `data-param` 路由协议。
* 使用现有 CSS token、卡片、按钮、徽章和折叠面板样式，仅补充摘要布局样式。
* 为摘要任务提供阶段展开和定位入口，不在摘要复制一份独立完成逻辑。

## Decision (ADR-lite)

**Context**: 时间轴完整但信息密度高，进入流程页的用户需要先做当前阶段决策，不应先扫描全部阶段。

**Decision**: 在完整时间轴之前增加无持久化且固定展示的当前阶段摘要。摘要只聚合已有阶段数据，提供下一步、风险、采购和验收四类入口；下一步只负责展开并定位，不复制完成控件；完整阶段卡和已有操作继续保留，首次进入时只展开当前阶段。

**Consequences**: 流程页首屏更可执行，且不会产生新的数据迁移；需要额外处理阶段参数、全完成、无任务和缺少采购/验收数据等空状态。
