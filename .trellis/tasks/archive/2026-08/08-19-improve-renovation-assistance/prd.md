# 进一步优化装修辅助体验

## Goal

把现有装修管家从“资料与进度记录工具”进一步提升为每天都能指导行动的装修作战台，降低用户遗漏任务、错过采购节点和预算失控的风险。

## What I Already Know

* 项目是零依赖、零构建的 vanilla JS / HTML / CSS 单页应用，数据保存在 localStorage。
* 现有模块包括首页、14 阶段流程、预算、指南、我的，以及空间需求派生任务。
* 首页已有当前阶段进度、预算概览、带日期待办、当前阶段避坑和快捷入口。
* 流程任务支持完成状态与日期，预算支持分类支出、超支提醒和 CSV 导出。

## Assumptions (Temporary)

* 本轮优先改善现有用户的日常决策体验，不引入后端、账号或第三方依赖。
* 以首页聚合和跨页面跳转为主，尽量复用已有任务、预算和建材数据模型。

## Open Questions

* 无。

## Requirements (Evolving)

* 首页应突出当前最重要的下一步行动，而不只是展示总体进度。
* 逾期任务、今天任务和未来 7 天任务应有清晰区分，并可直接进入对应流程阶段。
* 预算异常与采购提醒作为首页的次级风险提示，不能压过行动列表。
* 采购提醒应结合已有建材日历和当前阶段，提供近期可执行的采购入口。
* 无日期任务仍应提供低摩擦的下一步建议。
* 没有设置任务日期时，按流程顺序展示当前阶段前 3 个未完成任务，并提供进入流程页设置日期的入口。
* 首页行动项支持直接勾选完成，任务文字仍可进入对应流程阶段；完成状态与流程页即时一致。
* 首页增加轻量风险条，最多展示一个最严重的预算分类异常和一个当前阶段采购入口。
* 预算异常按超支金额选出最严重分类，展示分类名和超支金额并可进入预算页。
* 当前阶段存在采购数据时，展示采购入口并可进入建材日历；不在首页展开完整采购清单。
* 保持离线可用、现有数据兼容和移动端布局。

## Acceptance Criteria (Evolving)

* [ ] 已设置资料时，首页首屏能看到当前阶段和明确的下一步行动。
* [ ] 有逾期或临近日期任务时，首页按紧急程度呈现，并能点击进入对应阶段。
* [ ] 没有带日期的待办时，首页展示当前阶段前 3 个未完成任务。
* [ ] 在首页勾选行动项后，任务完成状态、当前阶段进度和总进度立即更新且与流程页一致。
* [ ] 预算分类超支时，首页以次级提醒指出分类与超支金额，并能进入预算页。
* [ ] 当前阶段存在近期采购节点时，首页以次级提醒展示相关提醒并跳转指南建材日历。
* [ ] 风险条最多呈现一个预算异常和一个采购入口，不挤占主行动区层级。
* [ ] 无资料、无任务、全部完成等状态仍有合理空状态和引导。
* [ ] 桌面端和窄屏移动端无明显溢出或重叠。
* [ ] 现有 lint / type-check / 可运行验证通过。

## Definition of Done

* 完成需求范围内的代码与样式调整。
* 保持现有 localStorage 数据结构兼容，必要时补充最小验证。
* 运行项目可用的静态检查或手工运行验证。
* 判断是否有新的项目规范或经验需要记录。

## Out of Scope

* 云同步、登录、多人协作和消息推送。
* 自动读取真实订单、实时市场报价或第三方地图/天气服务。
* 大规模重写现有页面或更换技术栈。
* 独立日历视图、系统通知和自动生成任务日期。
* 在首页展开全部预算异常或完整采购清单。

## Technical Notes

* 重点检查 `js/views/home.js`、`js/views/stages.js`、`js/views/guide.js`、`js/data/knowledge.js`、`js/app.js` 和 `css/style.css`。
* 路由通过 `data-action="nav"` 代理，首页入口应沿用该模式。
* 阶段任务和进度可通过 `App.stageTasks`、`App.currentStage`、`App.allProgress` 复用。

## Decision (ADR-lite)

**Context**: 装修过程信息多且时间节点分散，首页目前虽有提醒，但缺少明确的行动优先级。

**Decision**: 采用行动优先的首页作战台。以逾期、今天、未来 7 天和当前阶段下一项未完成任务组成主行动区；没有日期时按流程顺序展示当前阶段前 3 个未完成任务；行动项可直接勾选完成，文字可跳转对应阶段。辅助风险条最多呈现一个最严重预算分类异常和一个当前阶段采购入口。

**Consequences**: 用户每天打开首页即可获得明确下一步；首页需要处理日期缺失、跨阶段任务、全部完成和无资料等状态，但不引入新的持久化模型。
